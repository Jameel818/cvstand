# CVStand Templates Guide: Website = Word = PDF

> **What this file is for.** It covers how CVStand templates are built, edited, replaced and checked so that the **Word (.docx)** and **PDF** downloads look exactly like the template shown on the website. It collects what we learned in fidelity runs 4–14, the Arabic Word review (2026-10-06) and the typography spec (`CVSTAND_FONT_CONTROLS.md`).
>
> **Who reads it:** you, a teammate, or Claude Code. If you are Claude Code, read the whole file first, start in **Plan Mode**, and wait for approval before changing code.
>
> **Status markers used below**
> - ✅ **Confirmed**: decided or tested in earlier runs.
> - 🔍 **Verify in repo**: the path or name is our best knowledge but has not been checked against the current code. Check it and correct this file (see §15).

## 1. The golden rule

**The website preview is the master design.** The PDF and the Word file are copies of it and must match it.

| Output | How it is made | How close it must be |
|---|---|---|
| Website preview | HTML + CSS in the browser | This is the reference |
| PDF | The same HTML rendered by Playwright/Chromium | Should be pixel-identical to the preview |
| Word (.docx) | Rebuilt separately with python-docx (per-template Word design) | Visually identical: same layout, colours, fonts, sizes and page count. It must stay editable. |

Why Word needs the most care: the PDF comes from the **same HTML**, so it nearly matches by default. Word has **no HTML engine**, so every template is drawn a second time in Word's own language (tables, paragraphs, DrawingML shapes). Most of our fidelity bugs were on the Word side.

## 3. Architecture: where each part of a template lives

Single sources of truth. Never hard-code something in two places.

| Part | Location | Status |
|---|---|---|
| Template list / registry (key, block, label, blurb, skill pattern, accent, `ported`) | `app/registry.py`: `_MODERN`, `_ATS`, `_PORTED`, `TEMPLATES`, `get()`. A Python module, not JSON. There is no thumbnail field: gallery cards are rendered from the template itself. | ✅ |
| Template HTML (Jinja) | `app/templates/resumes/<group>/<block>.j2` (e.g. `app/templates/resumes/modern/t1.j2`, `app/templates/resumes/ats/t25.j2`); shared parts `app/templates/resumes/_macros.j2`, `_letter.j2`, `_letter_body.j2` | ✅ |
| Template CSS | **No per-template CSS file.** Each template's styles are inline `style="…"` attributes in its `.j2`. Shared document CSS (font links/inline faces, Arabic/RTL typography) is emitted by `app/rendering.py` (`document_html()`). `app/static/css/app.css` is the site shell (header, builder, gallery), not the résumés. | ✅ |
| Per-template **Word design** (python-docx builder) | **Modern:** `app/exporters/word_designs/t1.py` … `t24.py` (one module each, registered in `app/exporters/docx_design.py` `DESIGNS`; shared helpers `word_designs/common.py`, `docx_dml.py`, `docx_layout.py`). **ATS:** no per-template module: `app/exporters/docx_ats.py` builds every ATS .docx from the template's own markup. Entry point `app/exporters/docx.py`; letters `app/exporters/docx_letter.py`. | ✅ |
| Cover-letter themes | `app/letter_themes.json` (generated by `tools/build_letter_themes.py`; do not edit by hand), read by `app/letter.py`. Related: `app/letter_capacity.json` (`tools/build_letter_capacity.py`). | ✅ |
| Font registry (fonts, weights, sizes, defaults, `optical_scale`, `line_height`, `word_family_name`) | `app/typography/registry.py`, built from `app/typography/build.json`; calibration values in `app/typography/calibration.json`. There is no `registry.json`. | ✅ |
| Font files | `app/static/fonts/web/*.woff2` (preview/PDF), `app/static/fonts/ttf/*.ttf` (Word embedding), `app/static/fonts/licenses/`. The templates' own fonts are the `*.woff2` files directly in `app/static/fonts/`. | ✅ |
| Generated `@font-face` CSS | `app/static/fonts/typography.css` (typography-control faces, made by `tools/build_fonts.py`). The templates' own faces: `app/static/fonts/fonts.css` + `fonts_inline.css` (`tools/fetch_fonts.py`), Arabic `fonts_ar*.css`. | ✅ |
| Word font embedding | `app/exporters/docx_font_embed.py` → `embed_fonts()` | ✅ |
| Font build / calibration | `tools/build_fonts.py`, `tools/calibrate_fonts.py`, `/dev/typography` page | ✅ |

| Golden (reference) tests | `tests/golden/`: `html/{sample,sparse,gpa,partial}/<key>.html` checked by `tests/test_golden_html.py` (fast suite); `pixels/<key>.png` checked by `tests/test_golden_pixels.py` (`--e2e` only); `normalize/*.json`. Regenerate (with approval only) via `tools/golden.py --html` / `--pixels`. See `tests/golden/README.md`. | ✅ |
| Session log | `RESUME_HERE.md` (repo root) | ✅ |

**Rendering pipeline**

```
CV data (flat JSON, "language": "en" | "ar")
        │
        ├──► HTML template + CSS ──► Website preview
        │                     └──► Playwright: load page → document.fonts.ready
        │                          → fonts.load() each face → fonts.check() → page.pdf()  ──► PDF
        │
        └──► Word design for this template (python-docx)
              → save → embed_fonts() post-process ──► .docx
```

## 4. Lifecycle: adding a NEW template (start to finish)

Follow these steps in order, and finish each one before starting the next.

### Step 1: Design brief
- Pick the group (Modern or ATS), a name in **EN and AR**, a colour palette, and fonts from the **font registry only**.
- Write down every visual element, because each one will need a Word equivalent: bands, sidebars, page tint, timeline, pills, photo frame, skill bars/dots, icons, dividers.
- ⚠️ Avoid effects Word cannot reproduce (see §8.10). If the design needs one, agree on the Word fallback **before** building.

### Step 2: HTML + CSS (the master)
- Use **CSS variables** for fonts and sizes (`--font-heading`, `--font-heading-weight`, `--font-heading-size`, `--font-body`, …).
- Use **`pt`** sizes, not px, so Word's `Pt()` values can match exactly.
- Put `font-synthesis: none;` on the CV root.
- Size the page to **A4** and design for **one page** with typical content. Also test a long CV (see §9).
- Arabic: `dir="rtl"` on `<html>`, with `flex-direction: row` (**not** `row-reverse`). No `letter-spacing` and no `text-transform` on Arabic text.
- Phone numbers stay **LTR** inside Arabic CVs (wrap them in an LTR span or use `dir="ltr"`). ✅ This is done for all templates; repeat it in new ones.

### Step 3: Register the template
- Add it to the template registry (id, names, group, thumbnail).
- Add its cover-letter theme (letterhead = **the CV header exactly**, see §10).

### Step 4: PDF check
- Export EN and AR PDFs. They should already match the preview, because they use the same HTML.
- Run the PDF font check: every face is embedded under its exact name and there is no fallback font.

### Step 5: Word design (the hard part)
- Write the per-template Word design. Use the techniques in **§8** for each visual element from Step 1.
- Use the same pt sizes, colours (hex) and margins as the CSS.
- Map fonts with the Word weight rules (§7.3), set the Arabic run attributes (§7.4), and call `embed_fonts()`.

### Step 6: Compare (see §11)
- Take before/after screenshots, render the Word file in LibreOffice, compute a **diff %** against the PDF, then do the **Microsoft Word check**.

### Step 7: Tests
- Add the template to the golden tests (golden files are created or updated **only with approval**).
- Run the fast suite, the e2e suite, `verify_docker_context`, and `test_requirements_cover_imports`.

### Step 8: Save and release
- Use the save orders (§14) and work on a feature branch. **Never push `main`** without approval.

## 5. Lifecycle: EDITING an existing template

1. **Before** screenshots of the website, PDF and Word in EN and AR. Put them in a review folder on the Desktop. ✅ This is a required rule.
2. Change the HTML/CSS **and** the Word design **in the same change**. A change on one side only is a fidelity bug.
3. If you change a font, size or colour, change it in the source of truth (registry or CSS variable). Do not override it inside one output only.
4. **After** screenshots. Show them side by side with the before set.
5. Re-run the comparison (§11) and the tests (§12). Golden files change only with approval.
6. Check the **cover letter** too, because the letterhead copies the CV header.

## 6. Lifecycle: REPLACING or REMOVING a template

- **Replace (same id, new design):** follow §4 Steps 1–7 in full, keeping the id. Saved user CVs that use that id will show the new design. Decide whether that is acceptable before you start.
- **Remove:** don't delete an id that saved CVs may use. Instead hide it from the picker and map old CVs to a close replacement (agree on the mapping first). ✅ Today there is no per-id mapping table: `app/store.py` `load_meta()` sends any unknown or un-ported key to `registry.default_key()`, and taking a key out of `_PORTED` in `app/registry.py` hides it. A specific replacement mapping would be new code. Remove its Word design, letter theme, thumbnails and golden files in the same change.
- **Renumbering ids is not allowed.** Tests, saved CVs and docs all refer to them.

## 7. Typography and fonts (summary of `CVSTAND_FONT_CONTROLS.md`)

### 7.1 Rules ✅
- **One registry** holds all fonts, weights, sizes and defaults. UI, validation, CSS, PDF and Word all read from it.
- **Self-host every font.** Nothing is loaded from `fonts.googleapis.com` at render time.
- **Real weights only** (`font-synthesis: none`). Never offer a weight the font doesn't have.
- Sizes are in **pt** everywhere (CSS `pt`, docx `Pt()`).
- Per-font `optical_scale` and `line_height` (from calibration) are applied when rendering. The user's pt value stays as stored.
- **Step 7 calibration is currently OFF.** ✅ Turning it on changes Jomhuria, Bebas Neue and Lateef (bigger) and Amiri and Scheherazade (smaller). Only turn it on with approval and a full re-comparison.

### 7.2 Default Arabic fonts in PDF ✅
- Name: **Tajawal**. Headings: **Tajawal / Cairo**. Body: **IBM Plex Sans Arabic**.

### 7.3 Word font-name mapping ✅

| Weight | Word run font name | `bold` |
|---|---|---|
| 400 | `Family` | False |
| 700 | `Family` | True |
| other (200, 300, 800, 900) | `Family WeightName` (e.g. `Cairo ExtraLight`) | False |

The name must equal the TTF's **nameID 1** (`word_family_name` in the registry). Read it from the registry; never rebuild it in code.

### 7.4 Arabic runs in Word ✅
Every Arabic run needs:
- `w:rFonts` with **ascii, hAnsi, cs, eastAsia** all set
- `w:bCs` next to `w:b`, and `w:szCs` next to `w:sz`
- `<w:rtl w:val="1"/>` **and** `<w:lang w:bidi="ar-SA"/>` (a paragraph-level `<w:bidi/>` alone is not enough)

### 7.5 Embedding fonts in Word (required) ✅
Every .docx must embed the faces it uses, so it looks right on a PC without those fonts.
- `word/settings.xml`: `<w:embedTrueTypeFonts/>` at the schema-correct position, and **no** `w:saveSubsetFonts`.
- `word/fonts/fontN.odttf`: obfuscated with a new GUID. The key is the GUID's 16 byte pairs **in reverse order**; XOR the first 32 bytes.
- `word/fontTable.xml` entries (`embedRegular` / `embedBold`) plus their rels, and the `odttf` content type.
- Only embed fonts with **fsType 0 or 8**. Respect the OFL **Reserved Font Name** rule (no renamed or modified copies).
- Embed the full script-subset TTF, never only the characters used, so the user can keep editing.

### 7.6 The "Calibri" myth ✅
If Word shows **Calibri** in places, that comes from Microsoft 365 cloud fonts on that PC, not from our code. Check the embedded font list before "fixing" it.

### 7.7 Adding a NEW font
1. Add it to the registry (language, role, offered weights, category).
2. Run `tools/build_fonts.py`. It checks licences, RFN and fsType, builds woff2 + TTF, and regenerates `fonts.css`.
3. Run calibration for `optical_scale` / `line_height`, then look at it on `/dev/typography`.
4. Make sure `.dockerignore` does not exclude the font files (`tools/verify_docker_context.py`). A missing font **does not fail the build**; it silently falls back in production.

## 8. Word techniques: making Word look like the website

These are the techniques that worked in runs 4–14. Use them for every Modern template.

### 8.1 Page layout
- Same A4 size and margins as the CSS. Full-bleed elements (bands, sidebars) use **DrawingML shapes anchored to the page**, not table cells, so they reach the paper edge.
- `tblInd` to flush a table to the edge ✅: **-284 twips (LTR)**, **341 twips (RTL)**.

### 8.2 Sidebars and columns
- Draw the sidebar background as a **page-anchored DrawingML rectangle** that runs **from page top to page bottom**. A table-cell shading stops where the text stops (recurring bug #1).
- Put the sidebar text in a table column or text box on top of it.

### 8.3 Page background tint
- If the website page is tinted (light grey, off-white), Word needs a **full-page rectangle behind everything** (or the document background). Missing tint was recurring bug #2.

### 8.4 Header bands
- Draw them as page-anchored rectangles with the exact height from the CSS. Fixed in run 13b for t8, t13, t14 and t17 ✅. Missing band: recurring bug #5.

### 8.5 Timelines
- Draw the vertical **line** as a shape (a line, or a thin rectangle) **as well as** the dots. Missing lines: recurring bug #3.

### 8.6 Pills, chips and rounded boxes
- Use **rounded-rectangle** DrawingML shapes (`roundRect`). A shaded table cell gives a square box (recurring bug #4, t23 pill fixed in 13b ✅).

### 8.7 Photo frames
- Same shape, size and border as the website. Don't add an extra border. An empty photo slot must not show as a coloured block.

### 8.8 Sizes and wrapping
- Sidebar headings and labels in Word must use the **same pt** as the CSS. Longer Arabic headings (e.g. "المعلومات الشخصية") must not wrap. Check the column width (recurring bug #7).

### 8.9 RTL alignment ✅
- With `w:bidi="1"` on a paragraph, Word mirrors the alignment. RTL paragraphs need **`WD_ALIGN_PARAGRAPH.LEFT`** to appear right-aligned.
- Swap left and right for sidebars, borders and timeline sides in Arabic, matching the PDF (Arabic timeline and border sides were fixed in an earlier run ✅).

### 8.10 Things Word cannot do exactly (agree a fallback)
- Gradients, shadows, blur and CSS-only decorations are approximated with a flat colour or a shape.
- Complex skill sliders are simplified (accepted for التقنية المالية).
- Write the fallback into the template's notes so nobody "fixes" it later.

## 9. One page and long CVs

- **The page count must match.** If the PDF is 1 page, Word must be 1 page with the same sample content.
- LibreOffice often shows an extra page that Microsoft Word doesn't (10 Arabic templates in the 2026-10-06 review). **Microsoft Word is the judge.**
- With a long CV, both outputs must flow to page 2 cleanly: sidebars and tints repeat on page 2, and no section breaks mid-heading (t22 long-CV fix ✅).

## 11. Fidelity verification workflow (required for every visual change)

1. **Before/after screenshots** of the website, PDF and Word (page 1), EN + AR, in a Desktop review folder.
2. **Automated compare:** render the .docx with LibreOffice to PNG, compare it with the PDF page 1, and record a **diff %** per template.
   - Rough guide from the AR review: under ~10% = close; 10–20% = check; over 20% = something big is missing (band, tint, overflow). These are rules of thumb, not formal thresholds.
3. **Microsoft Word check (required):** LibreOffice findings are hints only. Confirm each issue in **Microsoft Word** before fixing it.
4. **Font-embedding check (before calling fonts "done"):** open the .docx on a **Windows PC where the fonts are NOT installed**. There must be no repair prompt, the fonts must be correct, and typing must keep the font. Record the Word version. A test on the developer PC proves nothing.
5. **Checklist per template** (tick every row in EN and AR):

| Check | ✔ |
|---|---|
| Same layout and column widths | |
| Sidebar reaches the page bottom | |
| Page tint present | |
| Header band present, correct height | |
| Timeline line + dots | |
| Pills rounded | |
| Same fonts (names) and pt sizes | |
| No heading wraps that the website doesn't have | |
| Same page count | |
| Phone numbers LTR in Arabic | |
| Photo frame matches | |
| Cover letter header = CV header | |
| Fonts embedded; opens with no repair prompt | |

## 14. Branches, saving and deploy rules ✅

- Work on a **feature branch**. **Never push or merge `main`** without the owner's explicit approval for that specific action.
- **Railway deploys automatically from `main`.** Pushing `main` = going live. The site is currently **offline by choice (private until launch)**: don't redeploy or "Deploy the repo" on Railway, and the private-preview lock must be in `main` before the site goes online again. (Turning off Railway auto-deploy is recommended.)
- **Don't touch:** env vars and secrets, the `/data` volume, DNS, or the root `Fonts/` folder (it stays excluded).
- **Secrets audit before every push:** `git ls-files` must show no `.env`, `*.db`, `venv/`, `data/resume.json` or keys.
- **Push form:** `GIT_TERMINAL_PROMPT=0 git -c credential.interactive=never -c core.askPass= push origin <branch>`, then confirm with `git ls-remote origin refs/heads/<branch>`.
- **Save orders** (end of every Claude Code session): update `RESUME_HERE.md` → secrets audit → commit → push the working branch → confirm with `git ls-remote` → confirm `git status` is clean.

## 16. Recurring pitfalls: quick list

| # | Symptom in Word | Cause | Fix |
|---|---|---|---|
| 1 | Sidebar stops before page bottom | Cell shading, not a shape | Page-anchored rectangle, full height (§8.2) |
| 2 | Page tint missing | No background shape | Full-page rectangle behind content (§8.3) |
| 3 | Timeline has dots but no line | Line not drawn | Add line shape (§8.5) |
| 4 | Pill is square | Table cell shading | `roundRect` shape (§8.6) |
| 5 | Header band missing | Band not drawn / wrong anchor | Page-anchored band, exact height (§8.4) |
| 6 | Extra page | LibreOffice metrics, or spacing too large | Confirm in MS Word; match pt spacing (§9) |
| 7 | Sidebar heading wraps / bigger | Wrong pt or column width | Match CSS pt and widths (§8.8) |
| 8 | Arabic alignment flipped | `w:bidi` mirroring | `WD_ALIGN_PARAGRAPH.LEFT` for RTL (§8.9) |
| 9 | Arabic shows in wrong font | `w:cs` missing | Set all four `rFonts` + `rtl` + `lang bidi` (§7.4) |
| 10 | Fonts wrong on another PC | Not embedded | `embed_fonts()`, check fsType (§7.5) |
| 11 | "Calibri" visible | M365 cloud fonts | Not a code bug (§7.6) |
| 12 | Phone number reversed in Arabic | Bidi reordering | Keep the number LTR (§4 Step 2) |
| 13 | Download crashes on Arabic filename | Non-ASCII in Content-Disposition | Strip non-ASCII from the filename ✅ |
| 14 | Font missing only in production | Font excluded from Docker image | `verify_docker_context.py` (§7.7) |
| 15 | Everything looks "plain" locally | Old shared single-user mode | Run `run.py` without `--server-store` (§13) |
